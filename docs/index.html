The problem

The return window closes quietly.

Distributors take expiring stock back, but only until a cutoff. Miss it by a week and the strip goes in the bin. Nobody has time to check 2,000 expiry dates against how fast each medicine sells.

90days before expiry: a typical return cutoff
5checks per batch before its cutoff; reminders only when at risk
₹0.05model cost per question or less, on open models
Printed at the bottom of a distributor invoice:
Expiry returns accepted up to 90 days before expiry against original invoice. E.&O.E.
ShelfMitra reads that line, works out the cutoff for every batch on the invoice, and starts watching each one the moment it is added.
How it works

The model reads. Code decides.

Open models transcribe and talk. Plain code checks every number, picks the action and fills in every figure you see.

1

Photograph the invoice

Qwen, an open-weight vision model, copies the table. Code checks batch format, MM/YY expiry, qty × rate = amount. Doubtful lines go to you, never guessed.

open model code checks
2

See what will not sell

TabPFN-3.5 predicts which batches will still be on the shelf at the cutoff. The shelf is sorted by rupees at risk, not by date.

TabPFN-3.5
3

Get reminded in time

A durable Temporal workflow per batch wakes at 60, 30, 14, 7 and 2 days before the cutoff. It survives restarts and crashes.

Temporal
4

Send it back in one tap

A WhatsApp return request to the distributor in Tamil, Hindi or English. The model writes the words once; code fills every batch, qty and date.

open model code fills numbers
5

Ask before you order

"Should I order 100 more Brufen?" The agent runs TabPFN on that order, counting stock already on your shelf, and suggests a safer quantity.

gpt-oss-120b TabPFN-3.5
6

Your data stays yours

One private database per shop. Run everything on the shop PC with Ollama by changing one setting. TabPFN already runs on CPU.

private by design
